# 伝わる文章ルール（詳細）

文章を読むのは、たいてい自分より忙しい相手。わかりにくい文章は、相手の時間と判断する力を奪う。理想は、相手が1行読んだだけで「それでOK」と先に進める状態。

書くことは考えることでもある。書いて初めて、論理（事実と理由の筋）と気持ち（本当に伝えたいこと・相手の受け取り方）が整う。以下のルールは、その2つを助けるための道具。

---

## A. 結論と構造

### 1. 冒頭で結論を言う
件名・1行目に「何をしてほしいか」「何が決まったか」を書く。経緯は後ろに回す。

```
NG: 先日の打ち合わせの件で、いくつか確認したいことがあります。
OK: 【確認】来週の撮影、10/8(水)午後で確定してよいですか？
```

### 2. 「〜について」「〜の件」で逃げない
テーマだけを示して中身を書かないと、相手は開くまで判断できない。

```
NG: 予算について
OK: 広告予算を月5万円 → 8万円に増やしたい
```

### 3. 全体から詳細へ
最初に全体像（いくつの話か・結論）、次に各論。いきなり細部から入らない。

### 4. 長文には冒頭に概要を付ける
5行を超えるなら、最初に2〜3行の要約を置く。

### 5. 列挙の前に数を言う
「確認したいことが3点あります」と先に言うと、相手は読む構えができる。

---

## B. 階層と箇条書き

### 6. 「■ → ◎ → ・」の階層で整理する
大見出しは ■、中見出しは ◎、中身は ・。同じ記号は同じ重さの情報にだけ使う。

```
■ 結論
来月から定例を週2回 → 週1回にしたい

■ 理由
◎ 時間
・週3時間 → 1.5時間に減る
◎ 中身
・直近4回のうち3回は報告だけで終わっている
```

### 7. 短い文章は階層化しない
要点が1つだけなら、記号を付けずに普通の文で書く。

### 8. 箇条書きは漏れなく・重複なく（MECE）
並べた項目同士が重なっていないか、大事なものが抜けていないかを確かめる。

### 9. 同じ階層は抽象度をそろえる
「売上」「SNS」「Instagram のリール」を同列に並べない。

### 10. 箇条書きの語尾をそろえる
「〜する」「〜すること」「〜。」を混ぜない。

### 11. 番号リストは順序・手順のときだけ
順番に意味が無いものには ・ を使う。

### 12. 同じ種類の情報が3つ以上続いたら箇条書きにする
文中に「AとBとCとD」と詰め込まない。

### 13. 記号を1つだけで使わない
・ が1行しか無いなら、記号を外して文にする。

---

## C. 中身の書き分け

### 14. 事実・解釈・提案を分ける
「起きたこと」「それをどう見るか」「だから何をするか」を混ぜない。

```
事実: 先月の問い合わせは42件、うち18件が送料の質問
解釈: 送料の表示が分かりにくい可能性が高い
提案: 商品ページの上部に送料を明記したい
```

### 15. 自分の意見・推奨をはっきり書く
「どうしましょう？」で相手に丸投げしない。「Aがおすすめです。理由は〜」と書く。

### 16. 選択肢は主なものを並べ、推奨を示す
選択肢ごとに良い点・悪い点を書き、最後に「→ 推奨：A（理由）」で締める。

### 17. 懸念と対策をセットで書く
相手が不安に思いそうな点を先回りして書き、その対策も添える。

### 18. 抽象的な言葉は中身を書く
「品質を上げる」「効率化」「早急に」は、人によって受け取り方が違う。何を・どれだけ・いつまでに、まで書く。

### 19. 用語は最後まで同じものを使う
「顧客」「お客様」「ユーザー」を混ぜると、別のものに見える。

### 20. リンクだけに頼らない
大事な数字や結論は本文に書く。リンクは補足として添える。

### 21. 具体例は引用やコードブロックで示す
例文・コマンド・テンプレートは、本文と見分けがつくように囲う。

### 22. 対比は構造で見せる
「Before / After」「今 / 変更後」は、表や2つの段落に分けて並べる。

---

## D. 日時・数字

### 23. 期限は日時まで書く
「なるはやで」「今週中に」ではなく「10/10(金) 17:00まで」。

### 24. 予定は確定した形で書く
「〜の予定です」「〜かもしれません」ではなく「10/8(水)に実施します」。未定なら「未定（10/6に決めます）」と書く。

---

## E. 文の作り方

### 25. 1文を短くする
1文に言いたいことは1つ。読点が3つを超えたら、文を分ける。

### 26. 順接の「が」でつながない
「〜ですが、〜します」の「が」が逆接でないなら、文を切る。

```
NG: 資料を確認しましたが、問題なかったので進めます。
OK: 資料を確認しました。問題なかったので進めます。
```

### 27. 「また」「さらに」を減らす
つなぎ言葉が続くなら、箇条書きにする方が読みやすい。

### 28. 意味の区切りで改行する
画面の端で自然に折り返させず、意味のまとまりごとに改行する。

### 29. コロン（：）は見出しの用途だけに使う
文の途中で「理由：〜」のように多用しない。

---

## F. 言葉づかい

### 30. 敬語は簡潔にする
「〜させていただけますと幸いでございます」は「〜してよいですか？」で足りる。丁寧さより分かりやすさを優先する。

### 31. 前置きのあいさつは省く
社内チャットでは「お疲れさまです」などの前置きを省き、1行目から本題に入ってよい（社外向けは相手の慣習に合わせる）。

### 32. 名前は「〜さん」を基本にする
役職呼びや呼び捨ては、相手やチームの慣習に合わせる。迷ったら「〜さん」。

### 33. 絵文字は目印として控えめに使う
注意（⚠️）・完了（✅）など、意味がはっきりするものだけ使う。

---

## 仕上げのチェック

- [ ] 1行目で結論、または相手へのお願いが分かる
- [ ] 事実・解釈・提案が混ざっていない
- [ ] 階層の記号が、重さのそろった情報にだけ付いている
- [ ] 日時・数字・抽象語が具体的になっている
- [ ] 推奨案と理由が書いてある（選択肢があるとき）
- [ ] 声に出して読んで、つっかえるところが無い

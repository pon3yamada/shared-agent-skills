# Plain Writing — 伝わる文章ルール

チャット・メール・ドキュメント・提案文を、**忙しい相手が一度読んだだけで判断できる形**に書く・直す。作法ではなく、考えを整理し、相手に最短で届けるための技術として使う。

## ひとことで言うと

- 件名と冒頭で**結論を先に**書く。相手が3秒で中身を判断できる状態を目指す
- 1文は短く、**情報は「■→◎→・」の階層**で整理する
- **事実・解釈・提案を分け**、選択肢を出すときは必ず推奨案を理由つきで示す
- 期限・数値・抽象語は**具体的に**書く（「なるはや」ではなく日時、「効率化」ではなく何をするか）

迷ったら「相手が一度読んだだけで、同じ情景が頭に浮かぶか」で判断する。

## 使い方

1. 書きたい内容・下書きを受け取る。相手（誰が読むか）と目的（読んだあと何をしてほしいか）が分からなければ、推奨案を添えて1つずつ確認する
2. 細かいルールが必要なときは読む → [references/rules.md](references/rules.md)
3. ルールに沿って下書き、または直した版を出す
4. 出す前に「結論が先頭か／階層が正しいか／事実・解釈・提案が分かれているか／具体的か」を確かめる

## 提案スキルとの関係

提案文書を作るときは `writing-proposals` と組み合わせてよい。材料集めは `writing-proposals`、文体・体裁はこのスキルを正とする。

## 出力の注意

- 貼り付け先（Slack・メール等）で崩れやすい markdown の装飾（`**` 太字・見出し記号）は使わない。記号の階層（■ / ◎ / ・）で構造を出す
- 完成した文面はコードブロックで出し、コピーしやすくする
